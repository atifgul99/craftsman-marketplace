
# Cross-Year Rules Register, TY2023–TY2026

Narrative companion to `rules/federal-<year>.json`. **Not consumed as data** —
`authority.md` still governs every value at point of use. This file exists to
make two things visible that a single-year file cannot show: how a parameter
moved across years, and what is scheduled to expire.

Built 2026-08-29 from primary sources (Rev. Proc. 2022-38, 2023-34, 2024-40,
2025-32; Notice 2022-55, 2025-67; Rev. Proc. 2022-24, 2025-19; Notice 2023-03;
PL 119-21), extracted with `pdftotext -layout`.

## 1. Why cross-year matters — a defect this register was built from

`federal-2024.json` shipped carrying the **2023** §179 figures ($1,160,000 cap /
$2,890,000 phaseout instead of $1,220,000 / $3,050,000). No single-year check
could see it: the values were internally consistent and schema-valid. It was
only visible against the adjacent year.

`evals/validate_rules.py` now enforces this mechanically. Finely-indexed
parameters must **strictly increase** year over year; coarser ones must be
**non-decreasing**; genuine statutory re-basings are declared in
`DRIFT_EXCEPTIONS`. Reintroducing the 2024 bug fails the suite with a named
message.

## 3. Statutory changes, not inflation

| Provision | Change | First affected year |
|---|---|---|
| **§179 cap / phaseout** | OBBBA raised to $2,500,000 / $4,000,000, **overriding** Rev. Proc. 2024-40's $1,250,000 / $3,130,000 | TY2025 |
| **§461(l) EBL threshold** | OBBBA **re-based downward** — the only decrease in the table, and a declared drift exception | TY2026 |
| **Bonus depreciation** | §168(k)(6) phase-down (80%/60%) replaced by an **acquisition-date** regime; property acquired after 2025-01-19 gets 100%. Two regimes coexist in 2025 | TY2025 |
| **§164(b)(6) SALT** | Flat $10,000 cap replaced by a raised cap **with its own income phaseout** | TY2025 |
| **Tips / overtime / senior / car-loan interest** | New OBBBA deductions, **statutory and unindexed** for the 2025–2028 window | TY2025 |
| **§174 → §174A** | Mandatory 5-year capitalization of domestic R&E replaced by immediate expensing | TY2025 |
| **SECURE 2.0 §109** | 60–63 "super" catch-up tier begins | TY2025 |
| **§67(g) → §67(h)** | Misc. itemized suspension re-enacted under a new subsection — cite the one matching the tax year | TY2026 |

⚠ **The OBBBA rows are why a year-agnostic answer is wrong here.** A 2025 or 2026
figure applied to a 2023 or 2024 return — or the reverse — is not a rounding
error; it is a different statute.

## 4. Expiry register

Verify each **before** relying on it for a target year.

| Provision | Status | Verify by |
|---|---|---|
| OBBBA tips / overtime / senior / car-loan deductions | Expire after **TY2028** | Any TY2029 planning |
| §108(a)(1)(E)/§108(h) QPRI exclusion | **Not permanent**, not extended by OBBBA | Every COD analysis |
| §168(k) acquisition-date regime | Verify the acquisition-date cliff each year | Every fixed-asset addition |
| Energy credits §25C / §25D / §30D / §25E | OBBBA set **termination dates in 2025** | Any credit claimed for a 2025+ install |
| §6511 refund window, TY2023 | Closes ~April 2027 for a timely-filed 2023 return | Before advising no action on TY2023 |

## 5. Shape differences across years — all intentional

| Difference | Years | Why |
|---|---|---|
| `bonus_depreciation_pct` scalar vs `bonus_depreciation` object | 2023–24 vs 2025–26 | Acquisition-date selection cannot be expressed as one annual percentage |
| `mileage_rates` interval array | 2026 only | 2026 had a mid-year rate change; other years have a single annual rate |
| `obbba_deductions` absent | 2023–24 | The statute did not exist |
| `ss_wage_base` null | 2023 | Source unreachable; fail-closed rather than guessed |

## 6. Freshness — these files expire

⚠ Every `federal-<year>.json` carries `_meta.stale_after`. Past that date the
file is **`AUTHORITY_HOLD` for numeric outputs** and `validate_rules.py` fails
with a dated message.

| File | Checked | Stale after | Window |
|---|---|---|---|
| `federal-2023.json` | 2026-08-29 | 2027-08-29 | 12 months — year closed |
| `federal-2024.json` | 2026-08-29 | 2027-08-29 | 12 months — year closed |
| `federal-2025.json` | 2026-08-29 | 2027-02-28 | 6 months — still being filed |
| `federal-2026.json` | 2026-08-29 | 2027-02-28 | 6 months — current year |

The risk being guarded is **legislation landing after the check**, not published
figures drifting. Re-verification means reading the cited sources *and* checking
what was enacted since — never bumping the date alone. Each file also records
`legislation_checked_through` (currently 2026-08-29), which is the question
elapsed time is only standing in for.

Reading a rules file goes through `evals/rules_freshness.load_rules()`, which
refuses to return expired data. `validate_rules.py` exits **2** when data is
expired and **1** when it is wrong.
